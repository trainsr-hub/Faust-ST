# Adaptive Hivemind Architecture & Agent Lifecycle

The Faust Hivemind is not a rigid, static organizational tree; it is an **evolutionary, adaptive system**.

### Foundational Principles:
1. **Antifragility over Static Perfection**:
   - No upfront structure remains optimal as projects evolve. Rigid hierarchies collapse under changing requirements.
   - The Hivemind dynamically spawns, edits, specializes, merges, and archives agent personas as work unfolds.

2. **Agent Lifecycle Stages**:
   - **Genesis (Spawn)**: Create a specialized Faust node when a distinct domain emerges requiring dedicated focus or segregated context.
   - **Mutation (Refinement)**: Continuously tune system prompts, allowed tools, and focus constraints based on real execution friction.
   - **Mitosis (Specialization)**: When an agent's domain becomes overloaded or diluted, split it into two specialized nodes.
   - **Archival (Dormancy)**: Retire finished or temporary personas into `.claude/agents/archive/` to preserve historical lineage without cluttering the active roster.

3. **Organic Memory Evolution**:
   - Domain memory partitions expand, consolidate, or archive alongside their corresponding agent personas.

**Why:** Prevents premature optimization, prevents system obsolescence, and ensures the multi-agent collective adapts organically to whatever challenges the Manager directs us toward.
**How to apply:** Treat all agent definitions in `.claude/agents/` as living organisms. Proactively propose spawning, splitting, or archiving personas as project complexity dictates.
